# 战略工作台

连接长期方向和每日行动的个人工作台。沿用静态 GitHub Pages 部署，无框架、构建步骤或线上依赖。

## 本地运行

在仓库目录执行：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

在浏览器访问该服务。页面使用 JavaScript 模块，需要通过 HTTP 服务运行，不能直接双击 `index.html`。

## 可以做什么

- 学习：添加和编辑项目、拆分步骤、勾选进展；修改步骤时保留未变化步骤的完成状态。
- 计划：在准备开始、正在推进、回顾与沉淀之间切换，也可以直接编辑状态。
- 待办与随手记：快速记录、编辑、删除，按五个长期方向筛选和搜索。
- 常用网站：添加、编辑、删除 HTTP(S) 入口。
- 实验空间：记录构想和开发状态，关联已发布工具的链接；不执行任意用户代码。
- 小工具：专注计时器、Unicode 文本计数、JSON 格式化与校验。
- 数据设置：JSON 导出、校验后确认导入、单独清除示例。新建及修改的记录会保留。

## 数据边界与恢复

内容仅保存在当前浏览器、当前网站来源的 localStorage 中，没有账户、云同步、模型 API 或 AI/ima 自动导入。更换域名、浏览器、设备或端口时，不会自动带走数据。不要在工作台保存 API 密钥。

请定期在“数据与备份”中导出 JSON。单个工作区和备份文件上限为 2 MiB，单类记录最多 1000 条；笔记最多 10000 个字符，项目步骤最多 100 项。

导入会替换整个工作区，必须先通过格式校验并由你确认。格式错误不会替换已有内容。若浏览器存储不可用或空间不足，页面会明确提示“仅暂存本页”，内容仍可导出，刷新前请先备份。

若原始存储损坏，应用保留原始记录并暂停普通写入。可在数据设置中下载原始数据后重建工作区，或从有效备份恢复。清理浏览器数据会删除本地记录；本页不能恢复已经清除且未备份的内容。

专注计时按真实经过时间计算，切换标签页后仍会校正。刷新或关闭页面会重置计时。

写入前会读取同一浏览器其他标签页的最新工作区，保留独立新增的内容。同一条记录在另一个标签页被修改时，旧编辑器会保留输入并提示重新打开最新记录，避免直接覆盖。

## 验证

数据和工具逻辑使用 Node 内置测试，无需安装 npm 包：

```sh
node --test tests/*.test.mjs
```

浏览器检查需要 Python Playwright 和 Chromium。云环境已提供它们：

```sh
python3 tests/browser_smoke.py
```

可用 `CHROMIUM_PATH` 指定 Chromium 路径，`COCKPIT_SCREENSHOTS` 指定截图目录。测试启动临时本地服务器，使用独立浏览器上下文，不会接触个人工作台数据。

`.github/workflows/pages.yml` 会在推送 `main` 后先运行数据与工具测试，再部署 GitHub Pages。发布包只包含网页及其运行所需的 CSS、JavaScript 模块，不包含开发文档和测试代码。
